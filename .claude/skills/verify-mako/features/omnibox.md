# Omnibox

The address bar is a raised card over the page, drawn like the sidebar's cards: the paper of the trail Enter lands in, ringed in that trail's colour. ⌘L (File → Open Location…) opens it on the current page's address to load something in this page; ⌘T opens it empty to start a trail, ⌥⌘T to open a page beneath this one, and ⌘F to find in the page. It takes a URL, a bare domain, or a search query, and as you type it lists up to eight suggestions under the field: pages already open in a trail first, then pages from history. While it is open a scrim dims the whole window, sidebar included, and a deep shadow lifts the panel, so an open omnibox is never missed. Find (⌘F) uses the same panel, quieter: plain paper, a thin ink ring and a magnifying glass. A status line under the field appears only for an error or a message.

## Sub-features

- `omni-open` ⌘L opens prefilled with the shown page's address (http, https, data or file), text selected; empty when no page is shown or it shows a notice.
- `omni-purpose` the field's accessibility label names what Enter does: `This page – search or enter address; Option-Return opens it beside this page` (⌘L), `New trail – search or enter address` (⌘T, or ⌘L with no page open), `New page beneath this one – search or enter address` (⌥⌘T), `Find in this page` (⌘F). On screen the colour and the glyph before the field say it (`omni-look`); the placeholder is `Search or enter address`, and `Find in page` for find. `makoctl tree` shows it as `placeholder=`.
- `omni-beside` in ⌘L with a page shown, Option-Return opens the address in a new page right after this one, under the same parent, and selects it; this page keeps its address. Beside a trail's root that is a new trail right after it, so the trail cap applies (`Can’t open: trail cap reached (N)`). Option-Return never puts a newline in the field. Other modes treat it as Return. `scripts/omnibox-keys-headed` checks it with real keys.
- `omni-url` input containing `://`, or starting `about:` or `data:`, loads as typed. A bare domain (a letters-only top-level domain of two or more), `localhost` or an IPv4 address, with an optional port and path, gets `https://`, or `http://` when it starts with `localhost` or `127.`.
- `omni-search` anything else goes to the config's `search =` engine (default Google).
- `omni-suggest` typing lists up to eight rows under the field, inside the card: open pages that match first (in sidebar order within the same match quality, pages inside collapsed ones included, each under its sidebar label), then history by match quality × frecency (`features/history.md`). Every typed word must match, in any case: the start of the address as typed scores highest, then the start of a title word or a part of the host, then the start of a path word, then anywhere else in the title or address. A history address that is open shows only as the open page. Each row shows the site's icon when Mako already holds it, else a globe (a suggestion never fetches one), the title, and the address without its scheme in a quieter ink, each cut with an ellipsis when long; an open page ends with its trail's dot and `Open`. The rows appear once something is typed: never on opening (⌘L opens on the page's address with none), never for an empty field, never in find.
- `omni-suggest-keys` ↓ and ↑ move a selection through the rows, starting from none: ↓ from none takes the first row, ↓ past the last returns to none, ↑ mirrors it. The selected row is tinted in the trail's colour; the typed text never changes. The pointer only tints the row under it more faintly and a click picks it, so a pointer resting where the list appears never changes what Return does. `scripts/omnibox-keys-headed` checks the keys.
- `omni-suggest-pick` with no row selected, Return and Option-Return do exactly what they did (`omni-url`, `omni-search`, `omni-beside`). With a row selected, or on a click or accessibility press of a row: an open page is shown (the core's `select`) and the omnibox closes, whatever it was opened for, with no page opened or loaded; a history row goes where its address typed would (⌘L into this page, ⌘T a new trail, ⌥⌘T a page beneath, Option-Return or an Option-click beside this page), the trail cap included.
- `omni-status` the line under the field (`mako.omnibox.status`, terracotta) shows only an error or a message: the cap refusal, `Not found` from find (cleared by the next hit), or else a config error. With none it is gone from the panel and the AX tree. Opening the omnibox again drops the last message.
- `omni-cap` at the trail cap, Enter for ⌘T beeps and leaves the panel open with `Can’t open: trail cap reached (N). ⌥⌘T opens a page in the current trail.`
- `omni-one-line` the field never wraps: a long address shrinks the font from 18 pt toward 11 pt to fit (18 × room ÷ width at 18 pt), past that it scrolls sideways; the panel keeps its height while typing. `scripts/ux-headed` shoots it with a long address.
- `omni-dismiss` Esc closes it without navigating; Enter on empty input does the same. So does a click anywhere outside the panel, on the page, the sidebar or any other part of the dimmed window: the click lands on the scrim (`mako.omnibox.scrim`, an AX button labelled Close address bar) and does nothing else, so a click meant to dismiss never follows a link or selects a row. Switching to another app leaves it open.
- `omni-scrim` the scrim is warm brown at 32% in light mode and black at 55% in dark mode.
- `omni-look` the panel is the trail's card colour (`NSColor.card`, the sidebar's paper with 18% of the trail's ink) inside a 3 pt ring of the trail's ink (`NSColor.trail`), in the trail Enter lands in: the active trail for ⌘L and ⌥⌘T, the colour the next trail would get for ⌘T or with no page open (the core's `next_color`, the lowest free slot). A glyph leads the field, drawn as the sidebar draws it: the root dot with its halo for a new trail, a plain dot for this page, a branch for a page beneath. The caret and selection take the trail's colour too (the field has its own field editor; the selection only shows the colour while Mako is the active app). Find is plain sidebar paper in a 1.5 pt ink ring at 60%, with a magnifying glass and the placeholder `Find in page`. Readable in both appearances, over white and dark pages.
- `omni-auto` it opens on its own, for a new trail, at launch when nothing was restored and no address was passed, and after the last page closes.
- `omni-find` ⌘F reuses the panel to find in the page (`features/trails.md`, `find`).

## How to get to it (user POV)

- Press ⌘L, or choose File → Open Location….
- ⌘T / File → New Trail, ⌥⌘T / File → New Page in Trail.
- ⌘F / Edit → Find….
- It opens on its own when no page is open.

## Driving it with makoctl

Preconditions: baseline, launched with `$C launch "" https://example.com`; `MAKO_BACKGROUND=1` is fine except for the steps marked (focus).

- **Open.** `$M $P menu File "Open Location…"`. `$M $P value mako.omnibox.field` prints `https://example.com/`; `$M $P tree | grep mako.omnibox.field` shows `desc="This page – search or enter address; Option-Return opens it beside this page"` and `exists mako.omnibox.status` exits 4. **(focus)** `key cmd+l` does the same.
- **Purposes.** `menu File "New Trail"`, `menu File "New Page in Trail"` and `menu Edit "Find…"` each put their purpose (above) in `mako.omnibox.field`'s `desc`, and none shows `mako.omnibox.status`.
- **Bare domain.** `menu File "Open Location…"; set mako.omnibox.field iana.org; confirm mako.omnibox.field`. `wait-title "Internet Assigned" 8` succeeds and `trails.json` still holds one page.
- **Local address.** With `fixture-server $PORT` running, the same with `127.0.0.1:$PORT/c.html`: `wait-title "Page C"`, and the page's `url` in `trails.json` starts `http://`.
- **Search.** The same with `rust lifetimes`: `wait-title "rust lifetimes" 8` (Google's results title).
- **Cap.** `menu File "New Trail"`, `set` an address, `confirm`, twice: three trails. A fourth: `value mako.omnibox.status | head -1` is `Can’t open: trail cap reached (3). ⌥⌘T opens a page in the current trail.` and `trails.json` still has three roots.
- **Dismiss.** `menu File "Open Location…"; set mako.omnibox.field ""; confirm mako.omnibox.field`: the panel closes and the title is unchanged. `menu File "New Trail"; set mako.omnibox.field "$U/c.html"; press-id mako.omnibox.scrim`: `exists mako.omnibox` exits 4 and `trails.json` is unchanged. **(focus)** `key cmd+l; type zzz; key escape`: title unchanged. `scripts/sidebar-headed` clicks the page and a sidebar row with the omnibox open, and switches apps.
- **On its own.** `$C stop; $C launch` (no address): `title` is `Mako`, `exists mako.blank` exits 0, the field's `desc` starts `New trail` and `exists mako.omnibox.status` exits 4.
- **Look.** `trails-ax` reads the ring's colour from a shot (its `ring` helper samples the top edge's middle, 0.75 pt out, and names the nearest trail ink or `neutral`): green (slot 0) for ⌘L on the first trail, blue (slot 1) for ⌘T then, blue for ⌥⌘T and ⌘L on the second trail, neutral for ⌘F. Each reading is kept beside its shot as `<shot>.ring.txt`. The placeholders are read from the tree. To see light mode on a dark Mac, launch a copy with `$C launch "" <url> -NSRequiresAquaSystemAppearance YES` (the extra arguments have no URL scheme, so Mako ignores them and AppKit reads them as a default).
- **Suggestions.** Serve `fixtures/omnibox` as `$U`, launch on `$U/one.html`, load `$U/two.html` into it (`menu File "Open Location…"; set …; confirm …`), then `menu File "New Trail"` to `$U/three.html`. `menu File "Open Location…"`: `exists mako.omnibox.suggestion.0` exits 4. `set mako.omnibox.field page; tree | grep suggestion`: rows 0 and 1 are `desc="Open page – …/two.html"` and `…/three.html`, row 2 is `title="Page one" desc="History – …/one.html"`, and none has `value="selected"`. `set mako.omnibox.field ""`: no rows. `menu Edit "Find…"; set mako.omnibox.field page`: no rows.
- **Pick an open page.** `menu File "New Trail"; set mako.omnibox.field two; press-id mako.omnibox.suggestion.0`: `exists mako.omnibox` exits 4, `trails.json` has `active` 1 and still two pages.
- **Pick history.** `menu File "Open Location…"; set mako.omnibox.field one; press-id mako.omnibox.suggestion.0`: this page's `url` becomes `…/one.html`, page count unchanged. The same press after `menu File "New Trail"` adds a root; after `menu File "New Page in Trail"`, a child of the active page.
- **(focus) Keys.** `key cmd+t; type two; key down`: `value mako.omnibox.suggestion.0` prints `selected`; `key return` shows that page. `scripts/omnibox-keys-headed` runs these.
- **Proof.** `$M $P tree 6 > $E/omni-tree.txt; $M $P shot $E/omni.png` with the panel open. `trails-ax` keeps `omnibox-this-page-green.png`, `omnibox-new-trail.png`, `omnibox-white-page.png`, `omnibox-child-blue.png`, `omnibox-dark-page.png` (`fixtures/trails/dark.html`), `omnibox-find.png` and `omnibox-cap-error.png`; `omnibox-ax` keeps `suggestions.png` and `suggestions-tree.txt`.

## Gotchas

- `mako.omnibox*` elements leave the AX tree while the panel is hidden (`exists` exits 4), so `exists mako.omnibox` proves the panel is showing.
- `v1.2`-style input is treated as search, not a domain, by design (the top-level domain must be letters).
- `set` on `mako.omnibox.field` reaches Mako as an edit, so the suggestions follow it (observed: `omnibox-ax` drives every row that way). Judge `omni-one-line` from typed input all the same, as `ux-headed` does.
- A suggestion row's `title` and `desc` in `tree` are cut at 80 characters; the row's tooltip and AX label hold the whole address.
- Rows are numbered in display order from 0 and renumbered on every edit, so read the row before pressing it.
- `exists mako.omnibox.status` exiting 4 is the no-message state, so read a message with `value` only right after the action that set it.
